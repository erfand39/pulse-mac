# معماری Pulse Mac

Electron Main مالک صف، وضعیت، مجوز مقصد و دسترسی ابزارهاست. React وضعیت و رویدادهای محدود را از طریق preload ایزوله دریافت می‌کند. BrowserWindow به عنوان پنجرهٔ بومی فرایند مانیتور شبکه را راه می‌اندازد. Main وضعیت Sleep/Wake را با powerMonitor مدیریت می‌کند. برنامه تنظیمات واقعی Login Item را از macOS می‌خواند و در Quit ابتدا انتقال‌ها و فرایندهای جانبی را متوقف می‌کند و بعد snapshot را می‌نویسد.

## ADR ۱، ذخیرهٔ اتمیک محلی

JSON اتمیک برای مدیریت حجم محدود دادهٔ یک پروفایل شخصی انتخاب شد. این طراحی وابستگی SQLite بومی و ABI اضافه برای Electron یا مرحلهٔ signing ندارد. سقف هر snapshot‏ ۶۴ MiB است و نوشتن‌ها سریالی‌اند. فایل موقت با دسترسی 0600 نوشته و fsync می‌شود، با rename جایگزین می‌شود و پوشهٔ حاوی آن نیز sync می‌شود. نسخهٔ معتبر قبلی به‌عنوان backup نگه داشته می‌شود. در بازیابی، قبل از نوشتن فایل اصلی، دادهٔ خراب حفظ می‌شود. مزیت SQLite برای پایگاه‌های بزرگ و queryهای جزئی در این طراحی وجود ندارد. نسخهٔ قدیمی با شناسه‌های موجود وارد می‌شود و یک snapshot معتبر در مسیر جدید از import مجدد جلوگیری می‌کند.

## فایل‌های دانلود

- هر دانلود HTTP یک پوشهٔ کار UUID، فایل part مستقل و checkpoint دارد. checkpoint شامل بازه‌های sync‌شده، هویت فایل در دیسک، اندازه و خلاصهٔ نشانی‌هاست. داده‌ها تا تأیید جریان کامل در قطعهٔ آخر committed نمی‌شوند.
- Range با ETag قوی، If-Range، offset، اندازه، طول و encoding معتبر اجرا می‌شود. تغییر هویت یا رفتار Range باعث شروع یک جریان تازه می‌شود. دادهٔ ناقص قبلی در پوشهٔ کار حفظ می‌شود. هرگونه SHA‑256 واردشده قبل از تکمیل بررسی می‌شود.
- انتشار HTTP با hard link انحصاری در همان volume انجام می‌شود. دربرخورد نام، پسوند عددی انتخاب می‌شود. پس از قطع در مرحلهٔ انتشار، نام نهایی و inode بررسی می‌شوند. مقصدهای فاقد hard link در مرحلهٔ انتشار خطا می‌دهند و فایل part می‌ماند. حذف در برنامه برای فایل HTTP ثبت‌شده با بررسی inode و تأیید بومی ممکن است.
- فایل‌های ویدئو و تورنت در پوشه‌های جدا برای هر وظیفه قرار می‌گیرند. ویدئو از مسیری که ابزار با قالب کنترل‌شده گزارش می‌کند نهایی می‌شود. WebTorrent پیش از بازکردن فایل‌ها، مسیرها و برخوردهای اسمی را بررسی و قطعه‌های موجود را دوباره اعتبارسنجی می‌کند. انتخاب فایل در snapshot جاری نگه داشته می‌شود. مرز قطعهٔ مشترک ممکن است بخشی از یک فایل انتخاب‌نشده را روی دیسک ایجاد کند.
- محدودیت سرعت HTTP روی همهٔ اتصال‌ها مشترک است. yt-dlp و WebTorrent محدودکننده‌های جداگانهٔ خود را دارند. مجموع سرعت این سه موتور تضمین سراسری ندارد. هنگام اجرای هم‌زمان فرایندهای جانبی، سقف هریک روی موتور خودش اعمال می‌شود.
- صف به‌ترتیب ورود شروع می‌شود و وظیفهٔ معطل را می‌توان از جزئیات به ابتدای صف منتقل کرد. عملیات تغییردهندهٔ یک task در Main سریالی اجرا می‌شوند و حذف و توقف برای پایان run و بسته‌شدن فایل‌ها منتظر می‌مانند. توقف در Sleep و offline وابسته به رویدادهای سیستم و Chromium است.
